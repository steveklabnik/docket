## Goal

`docket cleanup` (with no args) should find all workspaces whose changes have landed on trunk and clean them up automatically.

## Acceptance Criteria

- [ ] Find all `ws-*` directories adjacent to the repo
- [ ] For each workspace, check if its linked changes are in trunk
- [ ] If all changes merged, clean up the workspace (forget + rm)
- [ ] Report what was cleaned up
- [ ] `docket cleanup <id>` still works for explicit cleanup
- [ ] Consider having `docket sweep` call this after closing bugs

## Context

Current cleanup is manual - you must run `docket cleanup <id>` for each workspace. But if you've sent a PR and it merged, the workspace can be cleaned up automatically.

The flow becomes:
```bash
# In workspace
docket done           # finishes the bug

# Send PR, get it merged to trunk

# Later, from anywhere
docket cleanup        # finds and removes merged workspaces
```

This pairs well with `docket sweep` which already finds merged changes. Could either:
1. Have `sweep` call cleanup after closing bugs
2. Have `cleanup` call sweep's logic to detect merged changes
3. Keep them separate but share the "is merged" check
